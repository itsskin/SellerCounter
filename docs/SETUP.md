# Установка на плату

Предполагается, что MicroPython на ESP32-S3 уже прошит (см. лог с "MPY: soft
reboot" — значит да).

Все зависимости (`microdot`, `requests`) уже лежат прямо в проекте, в
`firmware/lib/` (см. `firmware/lib/VENDORED.md`) — отдельно ставить через
`mip`/терминал/интернет на плате ничего не нужно. Заливаешь `firmware/`
целиком — и плата сразу работает. Это специально сделано так, чтобы можно
было отдать прошитое устройство человеку без Thonny/терминала — прошёл
провижининг через веб-страницу, и всё.

## Вариант А — через Thonny (без терминала)

1. Открыть Thonny, подключиться к плате: **Run → Select interpreter…** →
   `MicroPython (ESP32)`, выбрать порт.
2. **View → Files** — откроются локальная и "MicroPython device" панели.
3. В локальной панели зайти в `firmware/` этого проекта, выделить всё
   содержимое (файлы верхнего уровня + папки `display/`, `lib/`,
   `marketplaces/`, `notifications/`, `utils/`, `www/`) → ПКМ → **Upload to /**.
   Thonny должен рекурсивно залить и подпапки; если версия старая и грузит
   только файлы верхнего уровня — заходи в каждую папку по очереди и грузи
   их так же, предварительно создав такую же папку на устройстве (ПКМ на
   панели устройства → New directory).
4. Проверить, что на устройстве появилось: `boot.py`, `main.py`, `config.py`,
   `wifi_manager.py`, `web_server.py`, `stats_engine.py`, `buzzer.py`,
   `display/` (включая **`display/assets/bg_200x200.bin`** — без него
   макет 200x200 рисуется на пустом фоне, без рамок/подписей, но не падает
   — и **`display/fonts/orbitron_52.py`**, **`display/fonts/orbitron_42.py`**,
   **`display/custom_font.py`**, **`display/png_to_bin.py`** — без них
   макет 200x200 не сможет импортироваться и отрисовка экрана будет падать
   с ошибкой в логах, хотя само устройство не зависает — см.
   `_safe_render`/`_redraw` в `main.py`/`stats_engine.py`. Файл
   `display/assets/layout.txt` заливать не нужно — создаётся сам с
   дефолтами при первом запуске, если его нет),
   `marketplaces/`, `notifications/` (файлы `.mid`/`.wav`), `utils/`, `www/`,
   `lib/microdot/`, `lib/sc_http/`, `lib/umidiparser/`.
5. Нажать Stop/Restart (или физический RESET) — плата поднимет точку
   доступа `SellerCounter-Setup` (пароль `12345678`, меняется в
   `config.py` до заливки).

## Смена фона и расположения текста на экране 200x200 (без компьютера)

Компьютер с Thonny/Pillow всё равно нужен, чтобы закинуть файл на плату —
но сама конвертация картинки происходит на самой плате, никакого PIL не
нужно.

**Сменить фон:**
1. Закинь на плату свою картинку `.png` (ровно 200x200) в `display/assets/`
   — имя любое.
2. Перезагрузи плату (Stop/Restart в Thonny или физический RESET).
3. Прошивка сама найдёт `.png` в этой папке, сконвертирует в
   `bg_200x200.bin` и удалит исходник — в логе будет строка вида
   `layout_200x200: <имя>.png стал новым фоном`. Если картинка не 200x200
   или PNG битый/экзотичный (интерлейс, 16 бит/канал) — в логе будет
   понятная ошибка, а файл всё равно удалится (чтобы не пытаться
   конвертировать его на каждой загрузке).

**Подвинуть/увеличить цифры выручки и заказов:**

Открой `display/assets/layout.txt` на плате (через Thonny) — там простым
текстом координаты и шрифт для каждого числа:

```
revenue.x = 100
revenue.y = 73
revenue.font = orbitron_52
revenue.max_width = 176

orders.x = 100
orders.y = 126
orders.font = orbitron_42
orders.max_width = 176
```

Меняешь числа, сохраняешь файл — подхватится на следующей перерисовке
экрана (при изменении данных), **перезагружать плату не нужно**. Опечатка
в одном поле не ломает весь экран — конкретно это поле откатится на
значение по умолчанию (см. лог).

`font` — имя файла из `display/fonts/` без `.py`. Если написать
несуществующее имя — в логе будет предупреждение и подставится
`orbitron_52`. Своих размеров шрифта на плате не сделать (нет
PIL/freetype) — новые генерируются офлайн `assets/generate_orbitron_font.py`
на компьютере, готовый `.py` заливается на плату как обычный файл.

## Вариант Б — через mpremote (терминал, для разработки)

```bash
pip install mpremote
cd firmware
mpremote connect PORT cp -r . :
mpremote connect PORT reset
```

`PORT` — `/dev/tty.usbmodemXXXX` (macOS) или `/dev/ttyUSB0` (Linux), можно
найти через `mpremote connect list`. Удобно на время активной разработки:
`mpremote mount .` — плата исполняет файлы прямо из этой папки без заливки
на каждое изменение.

## Первый запуск (оба варианта)

1. Подключиться к точке доступа `SellerCounter-Setup` с телефона/ноутбука,
   открыть в браузере `http://192.168.4.1/`.
2. Ввести Wi-Fi сеть, к которой должна подключиться плата, сохранить.
3. Плата перезагрузится и подключится к вашей сети — точка доступа при
   этом остаётся включённой (ESP32 держит AP+STA одновременно), так что
   `http://192.168.4.1/` работает всегда, а в ответе видно и IP, который
   плата получила от роутера.
4. Открыть веб-интерфейс (по IP из домашней сети или всё так же через
   `192.168.4.1`), добавить API-ключи маркетплейсов.

## Отладка (нужен Thonny/mpremote)

```bash
mpremote connect PORT repl
```

Живой REPL + вывод `print()` из прошивки — там же видно ошибки/исключения,
если что-то падает при старте. Это уже инструмент для разработчика, а не
для конечного получателя устройства.
